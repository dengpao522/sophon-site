demo.py — Full Integration Example 
from sophon import SophonClient

client = SophonClient(api_key="sophon-sk-****")

# —— Scenario: user first says HQ is in Shanghai; three months later, it's Hangzhou ——
client.memory.add(user_id="u1", messages=[
    {"role": "user", "content": "Our company HQ is in Shanghai"}])

client.memory.add(user_id="u1", messages=[
    {"role": "user", "content": "HQ moved to Hangzhou"}])
# State machine auto-arbitrates: old fact → superseded, new fact → active

# Current-state query: "what is true now"
client.memory.search(query="Where is the HQ?", user_id="u1")
# → HQ is in Hangzhou (old version auto-demoted)

# Historical query: "what was true then" — as_of travels back to any point in time
client.memory.search(query="Where is the HQ?", user_id="u1",
                    as_of="2025-06-01")
# → HQ was in Shanghai (hard-filtered by validity interval — never confused)

Why Sophon AI

Six core capabilities of ULM, built for high-compliance, long-horizon, multi-turn enterprise scenarios.

Bitemporal Queries

Two views over one memory graph: the current state answers "what is true now", the historical state answers "what was true then". When facts update, old and new versions coexist — history is never overwritten.

Deterministic State Machine

8 relation types (same / confirms / refines / contradicts / supersedes / cancels…) arbitrated by code, not the LLM — fact updates are explainable, replayable, and auditable.

LLM Extracts Candidates OnlyCode Makes the Rulings

Five-Channel Hybrid Retrieval

Dense semantic / Sparse BM25 / Graph multi-hop / Temporal chains / Topic rewriting — five recall channels fused by RRF ranking, so every channel's blind spots are covered by the others.

DenseBM25PPRRRF

Anti-Hallucination Refusal

The vigilance threshold: when evidence-query overlap is too low, the system explicitly refuses to answer instead of letting the model fabricate from weakly related memories. Better to say "I don't know" than to say it wrong.

vigilanceExplicit Refusal

End-to-End Provenance

Every memory carries provenance event IDs, traceable to an append-only immutable ledger. During audits, every answer can be reconstructed back to the original conversation.

provenanceImmutable Ledger

Write · Online

Write Path

  1. Append to the immutable ledger (append-only)
  2. Admission & splitting: only what's worth remembering gets remembered
  3. Atomize: one memory = one fact
  4. 5-dim labeling + deterministic constraint repair
  5. Version arbitration: state machine rules old/new relations
  6. Tiered persistence (L1–L6, six layers)
Read · Online

Read Path

  1. Five channels recall candidates in parallel
  2. RRF fusion ranking
  3. Triple modulation: retention / consolidation / status
  4. Compliance filter: access whitelist
  5. Budget packing: minimal memory set injection
  6. vigilance refusal + provenance returned
Maintain · Background

Maintenance Path

  1. Multi-factor forgetting: archive, not delete
  2. Consolidation & merge: the store converges, never bloats
  3. Evolution: old and new memories annotate each other
  4. Sleep-phase updates: heavy LLM ops moved off the online path
  5. Re-consolidation: local reorganization on retrieval hits
  6. Zero impact on online latency

Two Endpoints Cover Every Memory Need

One endpoint to write, one to search — REST style, JSON over HTTPS. The maintenance path runs asynchronously on the platform; no calls required.

Accepts raw conversations; internally it completes atomization → 5-dim labeling → deterministic version arbitration → tiered persistence. Supports user_id multi-user isolation and conversation_id conversation grouping.
