LEDGER 01 / WHY ULM

记忆不只是一个存储问题，
更是一个信任问题。

大模型从不缺"记得多"的方案，缺的是"记得清楚、经得起查"的方案。ULM 把每一条记忆变成一笔可验证的账目——写入前先过验证，输出时能拿出凭证，出错时能定位到端。

VALUE / 01

先验证，再入账

每条记忆写入前过三重验证器：规则校验毫秒级全量、权威源比对异步执行、代码实测挂睡眠期。未经证实的照样入账——但只带低信任标签，永远冒充不了事实。

VALUE / 02

答案附证据单

每个输出可附带 audit_bundle：引用了哪些记忆、各自信任等级、回溯到哪条原始事件、为何拒答。审计方拿到的不是一句解释，是一叠凭证。

VALUE / 03

出错三秒定位

错误不再是一团迷雾：引用全对仍出错 = 推理端问题；引用含存疑 = 证据端问题；无引用未拒答 = 假设端问题。排查一周，变成读一行结论。

LEDGER 02 / MECHANISM

一本 AI 读上千遍，
也不会被改坏的账。

四条铁律全部由确定性代码执行，LLM 无权裁决——这是"可信"二字能成立的原因。

01

只增不删APPEND-ONLY

记忆永不改写：发现错误不覆盖，只追加更正。任何一条结论都能回放到它写入的那一刻，没有人能"悄悄改口"。

#0421 风险=低（已作废·留痕）
#0431 风险=高 [supersedes #0421]
// 历史完整，可回放
02

验证盖章TRUST STAMPS

verified / unverified / refuted 三级信任标签，附连续置信度 κ 与完整验证记录。每个字都有出处和检验方式。

m = (内容, 出处, 时间, 标签,
    置信度 κ, 验证记录 v)
// κ ∈ [0,1] · 检验可复现
03

低不盖高VERIFICATION GATE

未验证的记忆无权推翻已验证的结论：冲突时不覆盖，改挂 disputed 并行披露。裁决由状态机执行——模型说了不算。

IF new.unverified AND old.verified:
  DENY supersedes
  LINK contradicts → DISPUTED
// 代码裁决 · 无权变通
04

宁拒不编REFUSE OVER HALLUCINATE

证据不足时明确拒答并说明原因，而不是用流畅的幻觉填充。拒答本身是一次可审计的行为，且低于阈值的证据永不拼接。

vigilance Σ < 0.15
→ REFUSE(reason=evidence_gap)
// 拒答留痕 · 进入审计包

错误三秒定位 · 诊断规则

IF 引用全 verified
且答案仍错问题在推理端——账是对的，想错了。
IF 引用含 unverified
或 refuted问题在证据端——账本已预警，可精确回溯。
IF 无引用
且未拒答问题在假设端——自由发挥，直接修策略。

错误定位从"排查一周"变成"读一行结论"。这是审计覆盖率与错误可定位率两个新指标的工程基础。
